1. Introduction

Purpose: The purpose of this document is to provide a High-Level Design (HLD) for the Ecommerce Microservices Platform. It defines the overall architecture, system components, data flows, and interactions between microservices.

Scope: This covers the core backend services required for a full-scale ecommerce platform, including User management, Product catalog, Cart operations, Order processing, Payments, and Notifications.

System Overview: The system is composed of 8 distinct services communicating via REST over an API Gateway. The platform follows the database-per-service pattern, utilizes service discovery for dynamic scaling, and implements centralized JWT authentication.

2. Architecture Overview

The system leverages a microservices architecture pattern utilizing Spring Cloud for robust discovery and routing.

  • Database per Service: Ensures loose coupling and independent scaling.
  • API Gateway Pattern: Single entry point routing requests and handling authentication.
  • Service Discovery: Eureka server enables services to find each other dynamically.

8. Security Architecture

Authentication is centralized at the API Gateway using JWT. Microservices trust the Gateway and use injected HTTP headers for user context.

Authenticated Request Client->>Gateway: GET /cart (Header: Authorization Bearer [Token]) Gateway->>Gateway: Validate Token Signature & Expiry Gateway->>Gateway: Extract userId, userEmail, userRole Gateway->>CartService: GET /cart (Headers: X-User-Id, X-User-Email, X-User-Role) CartService->>CartService: Process Request using X-User-Id CartService-->>Client: Cart Details

9. Caching Strategy

The Cart Service implements in-memory caching using Caffeine Cache to reduce database load for frequent cart reads.

  • @Cacheable(value = "carts", key = "#userId"): Applied to getCartByUserId() to serve data from memory if present.
  • @CacheEvict(value = "carts", key = "#userId"): Applied to addToCart(), removeFromCart(), and clearCart() to invalidate the cache upon modifications.
